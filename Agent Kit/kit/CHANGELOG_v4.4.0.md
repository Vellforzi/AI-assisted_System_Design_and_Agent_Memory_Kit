# Agent Memory Kit v4.4.0

Source date: 2026-10-20. Previous package version: 4.3.1.
This entry describes source changes. A matching version file or main commit is
not proof that a tag, GitHub Release or downstream installation exists.

## Engineering and communication

The two existing portable standards now require useful purpose explanations for
new or materially changed code, truthful parameter/result/collection types,
idiomatic code for supported language versions, justified exception boundaries
and cleanup of resources actually owned by the scope.

New references explain framework-visible type/docstring changes, preserving
absence and cancellation, avoiding speculative abstractions, discriminating
causal hypotheses, searching for confirmed defect variants, challenging review
findings and testing independent properties. The existing checklist was expanded
instead of adding a second review process or new skills for each concern.

The communication skill explains purpose, contracts, causes and limitations,
and points technical requirements to the engineering standard.

## Documentation and packaging

Root, tool, library, portable, Codex, Cursor and evaluation READMEs describe the
current core, optional quality pack and independently versioned memory module.
Stale release descriptions and fixed client role splits were corrected.
The five active evaluation cases retain their identities and introduction
history; current package metadata advances to 4.4.0.

Portable attribution is normalized to LF before hashing. Checkout attributes
keep distributed core and reference text stable across platforms, and a focused
regression check covers a root license checked out with CRLF. The library
checksum list describes the published Git contents, excluding unrelated local
edits.

The memory module remains version 0.1.1-local with its separate manifest. Its
earlier source addition is now included in this package's source history; this
update does not claim a separate module release or enable it automatically.

## Preserved boundaries

- The owner defines required semantics; unspecified behavior is preserved.
- Projects choose comment language, supported versions and static-analysis tools.
- No project paths, production credentials or product baseline are imported.
- No mandatory agent chain, new worktree, formatter or analyzer is installed.
- Core adoption preserves local project changes; optional packs require adoption.
- Structural checks and source review do not prove actual agent compliance.

## Verification scope

Publication checks cover metadata, links, synchronized skill copies, the
portable installer tests, existing contract-validator tests and package hashes.
Behavioral prompts require separate captured runs and grading.
