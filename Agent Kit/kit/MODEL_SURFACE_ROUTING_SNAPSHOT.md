# Model and Surface Routing Snapshot

Status: **historical evidence only**.
Captured at: 2026-07-10.
Expired at: 2026-08-09.

The model labels, context sizes, effort controls and provider UI observations in
older versions of this file are retained in Git history. They are not current
routing instructions.

## Current portable rule

ChatGPT web, Codex, Cursor and other connected agents are first-class execution
surfaces. Select a surface from current live capability evidence and task fit.
Do not hard-code that GPT web is external-research-only or that repository edits
must be performed by Cursor/Codex.

Exact model/settings advice requires one of:

- current owner-observed UI;
- current provider documentation;
- a current dated capability snapshot;
- a live local tool/model listing.

Keep separate:

- surface;
- model label or config slug;
- reasoning/effort;
- speed;
- context/capacity controls;
- delegation mode;
- shell/sandbox/runtime configuration.

Do not reuse controls from one surface as claims about another. Do not invent a
combined model label when the UI has separate fields.

## Routing decision

Choose the least expensive capable route for the actual task. Escalate only for
a concrete trigger such as protocol/schema changes, cross-system ambiguity,
production-risk repair, contradictory evidence or repeated failure of the
cheaper route.

The current owner request supplies action authority. A model or surface never
grants permission. A missing tool on one surface is a reason to choose another
capable surface, not a project-wide prohibition.

## Refresh trigger

Create a new dated snapshot when exact provider labels or controls are needed.
Do not edit this historical snapshot to pretend it is current.
