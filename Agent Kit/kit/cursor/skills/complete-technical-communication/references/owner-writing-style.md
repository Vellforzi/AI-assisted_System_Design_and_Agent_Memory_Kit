# Owner writing and explanation profile

> Starter profile. Customize this file from owner-authored technical samples.
> Treat it as style evidence, never as product or project truth.

## Core characteristics

The owner communicates by reconstructing the complete causal picture.

Preferred communication is:

- direct;
- explicit;
- technically precise;
- complete;
- logically ordered;
- transparent about evidence and uncertainty;
- detailed where relationships would otherwise be ambiguous;
- free of decorative corporate language.

## Required qualities

1. Preserve the complete meaning, not only the headline.
2. Explain relationships, not merely list components.
3. Use exact technical identifiers.
4. Distinguish business names from implementation names.
5. Explain why each important step exists.
6. Show producer, storage, cache, consumer and timing.
7. State exceptional and failure behavior.
8. State what is verified and what is not.
9. Avoid unexplained jumps in the causal chain.
10. Do not make the owner extract the actual logic through follow-up questions.

## Typical owner questions that the first answer should pre-empt

- Кто именно это делает?
- Откуда берётся это значение?
- Из какой таблицы?
- Кто записывает эту таблицу?
- Когда это происходит?
- Почему используется база, а не кеш?
- Есть ли эти данные в кеше?
- Какой ключ используется?
- Какой источник имеет приоритет?
- Что происходит, если данных нет?
- Что происходит при переходе дня?
- Как это связано с другим скрапером?
- Это название вкладки, компонента, таблицы или процесса?
- Что фактически проверено?
- Что ещё является предположением?

## Style boundaries

Do not imitate profanity, emotional intensity or conversational fragments unless
the owner explicitly requests that tone.

Match the owner's demand for completeness, precision, causal explanation and
plain language rather than copying surface mannerisms.
