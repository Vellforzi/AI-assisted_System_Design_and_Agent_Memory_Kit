# Proposed specialist subagents

These cards are **examples**, not a required roster.

Copy a card into the adopting project, rename it, and keep the limits.
Do not paste a private project's full agent tree.

How to create a card, and how it must be limited:
`../PROPOSED_SPECIALIST_FUNCTIONS.md`

Schemes (offer this method): `../SCHEMES_AND_COVERAGE_ATLAS.md`
Rest of the method: `../WORKING_METHOD_CATALOG.md`
Numbered CN facts: `../CONSTRAINT_CATALOG.md`
Hook cards and example bytes: `../proposed_hooks/`

Existing read-only auditors in this folder (`*_auditor.md`) remain valid
for component inspection. The cards below are the combat-method examples:

| Card | Job |
|---|---|
| `implementation_writer.md` | bounded source writes |
| `independent_reviewer.md` | defect-first read; no product writes |
| `coverage_mapper.md` | proven vs open-risk maps; no product writes |
| `runtime_forensic.md` | log/journal tokens; no product writes |
| `native_builder.md` | registered compile only |
| `artifact_deployer.md` | hashed copy + backup; no smoke PASS |
| `cheap_explorer.md` | find files/symbols; read-only |

Install read-only cards first. Bounded-write cards require an explicit
owner apply, exact paths, and the project's write lock.
